# Provider documentation audit — 2026-10-25

This audit covers the OpenAI and Anthropic contracts used by Agent Collab: launch configuration, model and effort selection, helper behavior, permissions, output, prompts, skills, packaging, and validation. It does not claim coverage of unrelated APIs or every page on either provider's site. Current official documentation was checked against the repository, Codex 0.164.0 source, and Claude Code 2.1.310. The affected Codex interfaces were also checked at the supported 0.163.0 floor.

## Corrections

1. **Codex memory independence.** `features.memories=false` alone can be undone by an inherited provider alias, `features.memory_tool=true`. Codex applies both merged feature keys and the latter wins. The launch now also sets `memories.use_memories=false` and `memories.generate_memories=false`. The first suppresses automatic memory context and dedicated memory tools even if the feature is enabled; the second disables memory-generation inputs. `--ephemeral` separately suppresses persistence and startup generation. Full-capability shell access still permits file reads, so the peer brief also prohibits consulting saved memories. [Configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference), [feature resolution](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/features/src/lib.rs), [memory extension](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/ext/memories/src/extension.rs)
2. **Linux safe-mode initialization.** Resolving an npm `codex` JavaScript launcher does not locate its platform package's bundled Bubblewrap. The preflight now runs `codex sandbox --permission-profile :read-only --cd <repo> -- <python> -c pass` with a finite timeout. Codex resolves its own backend. This uses the fixed built-in profile without managed-profile remapping to check OS capability; it does not attest the actual peer's effective permissions. The real peer still loads managed policy. The web sandbox guide's `codex sandbox linux` example differs from both supported CLI versions, so tagged source and current CLI help establish the command used here. [CLI implementation](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/cli/src/debug_sandbox.rs), [supported-floor implementation](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/cli/src/debug_sandbox.rs), [bundled backend resolution](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/linux-sandbox/src/bundled_bwrap.rs)
3. **Codex external message boards.** Inherited remote-board configuration can open a receiver during an ephemeral run and deliver external messages independently of memory settings. The launch now pins `features.agent_message_board=false`; ordinary native helper messaging remains available. This suppresses configured boards, subject to managed provider policy, and does not claim to block shell, MCP, or other external channels. [Board initialization and delivery](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/core/src/agent_message_board.rs), [receiver](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/agent-message-board-client/src/notifications.rs)
4. **Fresh Codex helper contexts.** Omitted `fork_turns` defaults to inherited history. Peer and host guidance now names `fork_turns="none"` explicitly and identifies this as an instruction; Claude fork controls remain provider-specific. [V2 spawn handler](https://github.com/openai/codex/blob/rust-v0.164.0/codex-rs/core/src/tools/handlers/multi_agents_v2/spawn.rs)
5. **Public-directory requirements.** OpenAI requires listing icons before submission and lists the license field as optional. Anthropic's checklist requires a license declaration but does not list an icon as a blocking requirement. The package lacks the icons required by OpenAI's documented Codex distribution metadata. Local validation and marketplace installation do not establish public-directory acceptance. [OpenAI submission](https://developers.openai.com/plugins/deploy/submission), [Anthropic checklist](https://claude.com/docs/plugins/pre-submission-checklist)

## Decisions and evidence limits

The follow-up review also corrected a broken memory-documentation anchor, added navigation to the synthesis reference, documented explicit Fable 5.1 selection without changing the named Fable 5 alias, and clarified project hook/MCP loading and Skill-triggered subagents. Claude outbound messaging and other external execution surfaces remain available under the established full-capability policy; the Agent-call counter is not a universal spawn limit. The configuration-reduced Claude availability probe does not observe every setting the real peer loads, so actual-run model and effort checks remain necessary.

The Astra/xhigh and Opus 5.5/xhigh defaults are explicit project choices. Anthropic recommends evaluating lower effort for cost and latency, but this audit supplies no comparative measurements that justify replacing the requested defaults. The opposite-product peer remains an independent verification step; neither the main-loop article nor either provider's skill guidance requires removing it.

The review combined independent host analysis, an OpenAI-focused helper, an opposite-product Agent Collab review, and advisory adjudication. The host verified adopted findings. Validation results are recorded in the README's evaluation section. This Linux audit does not establish native Windows/macOS behavior, a live npm-only safe-mode peer run, public-directory acceptance, or improved model quality, latency, or cost. Anthropic's combined All settings page could not be fetched; the relevant keys were checked through its feature-specific documentation.
